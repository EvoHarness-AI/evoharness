# 停放的点子（parked）

这里放**现在不做、将来某个条件成立时才值得判断**的东西。与 README / 交接文档的区别：那些记录"现在是什么"，这里记录"将来可能要什么，以及凭什么到时候还值得"。

关键设计：**"将来有用"是一个猜测，而会过期的正是这个猜测。** 所以每条都必须写清它依赖的前提，到点时先用现实检验前提，再决定做还是作废。

## 约定

每条必须有四行，`check-parked-triggers.mjs`（挂在 `npm run check` 链的 `check:parked`）会检查：

| 字段 | 含义 | 允许的写法 |
| --- | --- | --- |
| `条件：` | 什么现实出现就叫醒它 | `<glob> >= <n>`、`path_exists <路径>`、`仅复核` |
| `复核：` | 条件一直没成立时的兜底 | `review_by <YYYY-MM-DD>` |
| `前提：` | 今天认为"将来会需要"所依赖的那个判断 | 自由文本，但必须**可被现实推翻** |
| `判断依据：` | 到点时用什么标准决定 | 自由文本 |

到点就红。红了必须在**同一次改动**里三选一：

1. **做**——直接实现，实现完从本文件删除该条（git 历史即完成记录）。
2. **改条件**——前提仍成立、只是时机未到，写下观察到的新事实再推后。
3. **作废**——前提被现实推翻，删掉本条，理由写进删除它的那个提交信息（约定前缀 `PARKED-REJECT:`）。

没有第四种处理叫"留着以后再说"。`条件：仅复核` 是给"文件系统里没有任何可观测信号"的条目用的诚实写法——那种情况下不许编造代理指标，叫醒它的只有日期。

## 反模式（写之前自查）

- 前提写"以后可能有用"——不可证伪的条目等于僵尸，到点时你只会顺手续期。
- 为不可观测的触发编造代理指标（比如拿提交数猜"用户变多了"）——假精确比没有更糟，老实写 `仅复核`。
- 把 parked 当 TODO 用——**明确的、现在就该做的**事情直接做，或者进 issue，不放这里。
- 复核日期无限推后——推后必须伴随"观察到的新事实"，无事实的推后视同作废。

## 条目

### fd/rg 二进制的 npm 平台子包分发

- 来源：首次启动工具自举在 GitHub Releases 直连下 120s 超时的真实遭遇（2026-10-31）
- 条件：`仅复核`
- 复核：`review_by 2027-06-01`
- 前提：会出现无法用 winget/scoop 手动安装绕过、且 GitHub 直连不可达的场景（CI 环境、无管理员权限的用户、纯命令行环境）；在此之前 winget 路线已够用。
- 判断依据：到点查 issue/反馈里是否有"工具下载失败且无法手动绕过"的报告。有 → 仿 esbuild/biome 发行模式建 `@evoharness/fd-win32-x64` 等平台子包走 npm registry（国内可配 npmmirror 镜像），并附带 fd(MIT/Apache)/ripgrep(MIT/Unlicense) 的许可声明；没有 → 作废，确认个人使用场景 winget 已覆盖。

### management-http 代理支持

- 来源：同上遭遇；`src/utils/management-http.ts` 的 fetchWithRetry 无任何代理处理（已核实）
- 条件：`仅复核`
- 复核：`review_by 2026-12-15`
- 前提：自己已遇到一次超时（2026-10-31），靠 winget 手动绕过；会出现"无法用 winget 绕过、必须让 EvoHarness 自己走代理"的场景（最小权限环境、便携部署）。
- 判断依据：到点看是否出现过第二个此类场景。有 → 在 management-http.ts 接 undici ProxyAgent，复用 `core/http-dispatcher.ts` 现成的 proxy 逻辑，暴露 `EVOHARNESS_HTTP_PROXY`；没有 → 作废，确认 winget 路线稳定。

### EVOHARNESS_TOOLS_MIRROR 镜像源

- 来源：与上一条同源；npmmirror/ghproxy 类加速是国内网络下的另一条现实路径
- 条件：`仅复核`
- 复核：`review_by 2027-06-01`
- 前提：代理支持（上一条）实施后仍不够——存在"镜像前缀可解决、但代理不可用"的用户环境；或上游选择直接做镜像方案。
- 判断依据：上一条作废时本条自动重新评估；上一条做了 → 看其反馈里是否有"代理失败但镜像可用"的证据。有 → 给 tools-manager 加下载 URL 前缀可替换（环境变量），列出兼容的镜像形态；没有 → 作废。

### badlogic/pi 上游内核对比

- 来源：EvoHarness 是 pi 的快照 fork（2026-10-31 明确选择不做上游跟踪）；上游作者更新活跃
- 条件：`仅复核`
- 复核：`review_by 2027-06-01`
- 前提：上游会在内核机制（agent-loop、steering、compaction、evoharness-messages API）上继续演化出值得吸收的改进，且 EvoHarness 自己的改动没有分叉到无法借鉴。
- 判断依据：取一次 badlogic/pi 当前快照，人工 diff `packages/agent/src/agent-loop.ts` 与上游对应物，再看 release notes 里内核相关条目。发现至少一处值得吸收的行为改进 → 做一次对照迁移（人工对照，不合代码），并在本文件记一条新的 review 日期；没有 → 作废，确认 fork 已独立演化，这条 curiosity 成本不值得再付。

### 测试车道化（按 diff 选最小测试集）

- 条件：`packages/*/package.json >= 15`

- 前提：包数变多之后，全量测试的固定成本会开始逼人绕门禁（--no-verify、只跑局部）。

- 条件：`仅复核`
- 复核：`review_by 2026-12-01`
- 前提：会出现"从上游参考实现复制片段"导致的真实带入（当前存量计数为 0，无可观测信号表达"开始带入了"）。
